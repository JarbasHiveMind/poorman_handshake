# AGENTS.md — `poorman_handshake`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

`poorman_handshake` is the cryptographic bootstrap primitive for the HiveMind
mesh: it lets two nodes derive a shared session secret over an insecure channel
before an encrypted channel is raised. It ships three handshake families —
`NoiseHandShake` (Noise Protocol Framework, `Noise_XXpsk2` / `Noise_KKpsk0` over
X25519 + ChaCha20-Poly1305, forward secrecy, this is HiveMind protocol v3, and
the recommended path for new code), `PasswordHandShake` (legacy PBKDF2-derived
shared key, no forward secrecy, on-wire verifier is an offline-crackable image
of the password), and `HandShake`/`HalfHandShake` (legacy RSA key agreement, no
forward secrecy). Part of the [HiveMind](https://github.com/JarbasHiveMind)
ecosystem — a protocol for connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). The hub is
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core), which depends
on this library for its handshake layer. See [`docs/security.md`](docs/security.md)
for the full cryptographic analysis and [`docs/protocol.md`](docs/protocol.md)
for the wire format.

## Layout / build / test

- Package module: `poorman_handshake/`, with `asymmetric/` (RSA), `symmetric/`
  (password handshake + strength check), and `noise/` (Noise handshake)
  subpackages. Tests live in `tests/` (check before adding — do not create a
  second test directory).
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[test]" --prerelease=allow`
- Run the suite in the foreground: `python3 -m pytest tests/ -q`. No live-hub
  or network dependency — the suite exercises handshakes in-process, both
  peers instantiated locally.
- CI (`.github/workflows/`) runs the shared OVOS build-tests matrix on Python
  3.10–3.13, ruff lint, coverage, and license-check.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is a
  bug to FIX at the source, not to work around with a pin downgrade.

## Repo-specific rules

- **Never weaken a security check for convenience.** `check_password_strength`
  (in `poorman_handshake/symmetric/strength.py`) enforces `min_bits` (default
  `DEFAULT_MIN_BITS`) via `zxcvbn` and raises `WeakPasswordError` below that
  threshold — this gate is deliberate, not a false positive to relax. It only
  disables when a caller explicitly passes `min_bits=0`; do not lower the
  default or bypass the check in library code to make a test or example pass.
- `HandShake`/`HalfHandShake` (RSA) and `PasswordHandShake` have **no forward
  secrecy** — a compromised long-term key/password exposes every past session.
  `NoiseHandShake` is the preferred path for new code; only extend the legacy
  handshakes for interoperability with already-deployed peers, and say so in
  the PR if that's the reason.
- `load_RSA_key` (`poorman_handshake/asymmetric/utils.py`) memoizes by
  **content digest** (`sha256` of the PEM bytes), never by mtime or file size —
  same-size rewrites within one filesystem timestamp tick would otherwise keep
  a rotated key active. Any new memoization in this library follows the same
  rule: key on content, invalidate on content change, and cache only pure
  functions (the imported key object must never be mutated by callers).
- **Changing the wire handshake format breaks every deployed node.** Any change
  to the Noise message patterns/tokens, the password-handshake verifier
  encoding, or the RSA exchange payload shape is a protocol version change —
  treat it with the same care as a HiveMind spec change, document it in
  `docs/protocol.md`, and never make it silently backward-incompatible.
- Test harnesses in this repo (`tests/`) cover the crypto primitives directly
  (handshake correctness, key caching, password-strength gating) — they are
  not a substitute for HiveMind end-to-end routing-conformance testing, which
  lives in the harness/architecture repos.
